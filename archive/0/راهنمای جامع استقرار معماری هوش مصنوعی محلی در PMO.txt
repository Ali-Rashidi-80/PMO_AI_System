راهنمای جامع و عملیاتی استقرار معماری عدم اعتماد هوش مصنوعی (PMO)

مبتنی بر n8n، LM Studio (Gemma 4 & Qwen 3.6) و Qdrant

این مستند بر اساس معماری ارائه شده در مقاله شما تهیه شده است. هدف، ایجاد یک پایپ‌لاین کاملاً آفلاین برای تولید نامه‌های اداری و استخراج ریسک‌ها بدون نشت داده است.

فاز ۱: پیش‌نیازهای زیرساختی

قبل از شروع، اطمینان حاصل کنید که سیستم عامل شما (ویندوز، لینوکس یا مک) دارای موارد زیر است:

سخت‌افزار: حداقل ۳۲ گیگابایت رم (ترجیحاً ۶۴ گیگابایت مک یا سیستمی با کارت گرافیک RTX 3090/4090 با 24GB VRAM).

نرم‌افزارها:

نصب Docker Desktop (یا Docker Engine در لینوکس) و Docker Compose.

نصب LM Studio (نسخه 0.3.x یا جدیدتر).

فاز ۲: استقرار زیرساخت ارکستراسیون (n8n و Qdrant)

ما از Docker Compose برای راه‌اندازی n8n (به عنوان مغز متفکر گردش‌کار) و Qdrant (به عنوان پایگاه داده برداری برای RAG) استفاده می‌کنیم. در این ساختار از ایمیج‌های لوکال (میرور چابکان) استفاده شده است تا سرعت اجرا به حداکثر برسد و مشکل شبکه وجود نداشته باشد.

۱. در سیستم خود یک پوشه به نام pmo-ai-automation بسازید.
۲. درون آن یک فایل متنی با نام docker-compose.yml ایجاد کرده و کدهای زیر را در آن قرار دهید:

version: '3.8'

volumes:
  n8n_data:
  qdrant_data:

services:
  qdrant:
    # استفاده از ایمیج موجود در سیستم شما
    image: mirror2.chabokan.net/qdrant/qdrant:latest
    container_name: qdrant_pmo
    restart: unless-stopped
    ports:
      - 6333:6333
      - 6334:6334
    volumes:
      - qdrant_data:/qdrant/storage

  n8n:
    # استفاده از ایمیج موجود در سیستم شما
    image: mirror2.chabokan.net/n8nio/n8n:latest
    container_name: n8n_pmo
    restart: unless-stopped
    ports:
      - 5678:5678
    environment:
      - N8N_HOST=localhost
      - N8N_PORT=5678
      - N8N_PROTOCOL=http
      - NODE_ENV=production
      - WEBHOOK_URL=http://localhost:5678/
      - GENERIC_TIMEZONE=Asia/Tehran
      # فعال‌سازی قابلیت‌های هوش مصنوعی پیشرفته در n8n
      - N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS=true
      # جلوگیری از خطای Timeout در هنگام کار با مدل‌های سنگین پردازش محلی
      - N8N_HTTP_REQUEST_TIMEOUT=300000 
    volumes:
      - n8n_data:/home/node/.n8n
      # نگاشت پوشه اسناد لوکال به داخل کانتینر برای خواندن فایل‌های PMO
      - ./local_documents:/data/documents
    depends_on:
      - qdrant
    # این دستور برای ارتباط n8n درون داکر با LM Studio روی ویندوز/مک حیاتی است
    extra_hosts:
      - "host.docker.internal:host-gateway"


۳. در همان مسیر اصلی (pmo-ai-automation)، یک پوشه به نام local_documents بسازید (فایل‌های PDF و Word کارگاهی را بعداً اینجا می‌ریزیم).
۴. ترمینال/CMD را در این مسیر باز کرده و دستور زیر را اجرا کنید:
docker-compose up -d

اکنون n8n روی پورت localhost:5678 و Qdrant روی پورت localhost:6333 در دسترس هستند.

فاز ۳: پیکربندی موتور استنتاج (LM Studio)

نرم‌افزار LM Studio را باز کنید. ما باید مدل‌های اشاره شده در مقاله را دانلود کنیم.

۱. دانلود مدل‌ها:
در نوار جستجوی LM Studio، موارد زیر را جستجو و نسخه‌های GGUF مشخص شده را دانلود کنید:

مدل تحلیل‌گر و نامه‌نگار: gemma-4-26b-it-moe (نسخه Q4_K_M.gguf را انتخاب کنید تا رم کمتری مصرف کند - حدود 16GB).

مدل استدلال‌گر و عامل هوشمند: qwen-3.6-35b-a3b (نسخه Q6_K.gguf یا Q4_K_M.gguf).

مدل تعبیه‌ساز (Embedding): nomic-embed-text-v1.5.gguf (بسیار سبک است).

۲. راه‌اندازی سرور محلی (Local Server):

به تب Local Server (آیکون دو فلش) در منوی سمت چپ LM Studio بروید.

مدل gemma-4-26b را از نوار بالا بارگذاری (Load) کنید. در تنظیمات سمت راست (Hardware Settings)، تیک GPU Offload را روی Max بگذارید.

بسیار مهم: در بخش Text Embedding، مدل nomic-embed-text را نیز فعال (Load) کنید.

روی دکمه سبز رنگ Start Server کلیک کنید.

اکنون API محلی شما روی آدرس http://localhost:1234/v1 در حال کار است.

فاز ۴: اتصال n8n به هوش مصنوعی محلی

۱. مرورگر را باز کرده و به http://localhost:5678 بروید. (در اولین ورود، اکانت ادمین بسازید).
۲. در n8n به منوی Credentials بروید و اتصالات زیر را بسازید:

اتصال Qdrant:

نوع: Qdrant Api

آدرس: http://qdrant_pmo:6333 (چون هر دو در داکر هستند از نام کانتینر استفاده می‌کنیم).

نیازی به API Key نیست.

اتصال OpenAI (برای فریب n8n جهت وصل شدن به LM Studio):

نوع: OpenAI API

در بخش API Key بنویسید: lm-studio (مهم نیست چه می‌نویسید، فقط خالی نباشد).

در پایین صفحه، گزینه تنظیمات پیشرفته (Advanced) را باز کنید.

Base URL را به این آدرس تغییر دهید: http://host.docker.internal:1234/v1 (این دستور باعث می‌شود n8n از داخل داکر به ویندوز/مک شما وصل شود).

فاز ۵: سناریو الف - طراحی پایپ‌لاین RAG و نامه‌نگاری (اجرایی در n8n)

بخش اول: تزریق اسناد به حافظه (Ingestion Workflow)

شما باید یک Workflow بسازید که اسناد پوشه local_documents را خوانده و به Qdrant بفرستد.

نودهای مورد نیاز در n8n (به ترتیب):

Read Files from Disk: مسیر را روی /data/documents/ تنظیم کنید.

Extract from File: برای استخراج متن از فایل‌های PDF یا Word.

Advanced AI -> Vector Store -> Qdrant:

حالت را روی Insert Documents بگذارید.

نام کالکشن (Collection Name): pmo_knowledge_base

توابع جانبی برای Qdrant:

به ورودی Document در نود Qdrant، یک نود Default Data Loader متصل کنید.

به ورودی Text Splitter، نود Recursive Character Text Splitter را وصل کنید (Chunk Size: 1000, Overlap: 200).

به ورودی Embedding، نود OpenAI Embeddings را وصل کنید. در تنظیمات آن، نام مدل را دقیقاً nomic-embed-text-v1.5 تایپ کنید (یا نامی که در LM Studio نمایش داده می‌شود).

بخش دوم: گردش‌کار نگارش نامه هوشمند (Letter Generator Workflow)

این Workflow درخواست کاربر را می‌گیرد، در اسناد می‌گردد و نامه را با Gemma 4 می‌نویسد.

نودهای مورد نیاز:

Webhook / Form Trigger: یک فرم ساده برای دریافت اطلاعات از مهندس (مثلاً فیلد "موضوع نامه" و "نام پیمانکار").

Advanced AI -> AI Agent:

مدل (Language Model): نود OpenAI Chat Model را متصل کنید. در تنظیمات مدل، نام را دقیقاً برابر نام مدل درون LM Studio (مثلاً gemma-4-26b-it-moe-Q4_K_M) قرار دهید.

تنظیمات مدل: Temperature: 0.2 (برای متون رسمی حقوقی باید پایین باشد).

ابزار (Tools): نود Vector Store Tool را وصل کنید.

آن را به Qdrant متصل کنید (کالکشن: pmo_knowledge_base).

توضیحات ابزار (Description): "Use this tool to search through PMO documents, contracts, and past delay records."

مدل Embedding را مجدداً OpenAI Embeddings با مدل nomic تنظیم کنید.

الگوی دستوری (System Prompt) برای نود AI Agent:

شما یک مدیر حقوقی و کارشناس ارشد دفتر مدیریت پروژه (PMO) هستید. 
وظیفه شما نگارش نامه‌های رسمی، مستدل و حقوقی به پیمانکاران است.
همواره از ابزار جستجوی اسناد (Vector Store Tool) برای یافتن سوابق تأخیرات و بندهای جریمه مربوط به پیمانکار استفاده کنید.

ساختار نامه خروجی باید شامل موارد زیر باشد:
1. تاریخ و شماره نامه (فرضی)
2. موضوع نامه
3. مقدمه رسمی
4. اشاره دقیق به بندهای قرارداد و سوابق (استخراج شده از ابزار)
5. هشدارها و الزامات
6. مهر و امضای دفتر مدیریت پروژه

لحن شما باید کاملاً رسمی، قاطع و مطابق با استانداردهای اداری ایران باشد. هرگز اطلاعاتی را از خودتان جعل نکنید (No Hallucination). اگر سندی یافت نشد، در نامه ذکر کنید که "پیرو بررسی‌های اولیه...".
<|think|> پیش از نگارش، ابتدا اسناد را بررسی کن و استدلال خود را بساز.


فاز ۶: سناریو ب - اتوماسیون چند عاملی برای استخراج ریسک (Multi-Agent با Qwen 3.6)

این پیشرفته‌ترین بخش مقاله شماست. در اینجا ما مدل توانمند Qwen را برای تحلیل منطقی بارگذاری می‌کنیم.
در LM Studio، مدل Gemma را Unload کرده و Qwen 3.6 را Load کنید.

در n8n، یک Workflow جدید بسازید:

Schedule Trigger: تنظیم کنید تا هر جمعه ساعت 4 عصر اجرا شود.

Read Files: خواندن گزارش‌های روزانه از یک پوشه خاص (/data/documents/weekly_reports).

Advanced AI -> AI Agent (حالت Planner / Supervisor):

مدل: OpenAI Chat Model (متصل به LM Studio و نام مدل Qwen 3.6 تنظیم شود).

پرامپت سیستمی: "شما مدیر ارشد ریسک هستید. متن گزارشات را بخوانید و هرگونه نشانه‌ای از تأخیر، مشکلات مالی پیمانکار، یا کمبود مصالح را استخراج کنید."

ابزارهای متصل به عامل (Tools):

Code Node Tool: برای اجرای اسکریپت‌های پایتون/جاوا اسکریپت در صورت نیاز به محاسبات تاخیر.

Information Extractor Tool: برای تبدیل متون نامنظم به یک خروجی JSON ساختاریافته (جدول ریسک‌ها).

الگوی استخراج خروجی (JSON Schema) در ابزار عامل:
در تنظیمات عامل هوشمند، خروجی را ملزم به ارائه ساختار JSON زیر کنید تا مستقیماً به داشبورد مدیریتی برود:

{
  "project_risks": [
    {
      "risk_title": "عنوان ریسک",
      "severity": "High/Medium/Low",
      "evidence": "جمله دقیق استخراج شده از گزارش",
      "recommended_action": "پیشنهاد مدل برای مدیریت ریسک"
    }
  ]
}


فاز ۷: نکات کلیدی تست و بهینه‌سازی (Best Practices)

مدیریت حافظه (RAM/VRAM): مدل‌های Gemma 4 26B و Qwen 3.6 35B بسیار بزرگ هستند. اجرای همزمان آن‌ها به شدت نیازمند حافظه است. در محیط‌های واقعی PMO که یک سرور واحد دارند، یک مدل را فعال نگه دارید (توصیه: از Qwen 3.6 برای تمام کارهای تحلیلی و از مدل‌های کوچکتر مانند Llama-3-8B-Instruct صرفاً برای مرتب‌سازی متون استفاده کنید).

Zero Data Leakage: با توجه به عدم اتصال کانتینرهای Docker به شبکه‌های خارجی (جز نگاشت پورت محلی) و استفاده از LM Studio، داده‌های سازمان شما هرگز از سخت‌افزارتان خارج نمی‌شود. برای اطمینان بیشتر در سیستم‌عامل میزبان، می‌توانید با فایروال دسترسی LM Studio به اینترنت را پس از دانلود مدل‌ها کاملاً مسدود کنید.

توسعه با ایمیج‌های موجود شما: شما ایمیج‌های postgres و redis را نیز روی سیستم خود دارید. در صورتی که تصمیم گرفتید این سیستم را به عنوان سرویس دائمی (Production) در سازمان پیاده کنید، می‌توانیم بعداً فایل docker-compose.yml را مجدداً به‌روزرسانی کنیم تا n8n به جای دیتابیس ساده داخلی (SQLite)، به کانتینر Postgres متصل شود تا پایداری و امنیت داده‌های گردش‌کار شما بیشتر شود. فعلاً برای فاز تست و استقرار سریع، تنظیمات فعلی کاملاً پاسخگوست.

با اجرای دقیق این مراحل، معماری عدم اعتماد (Zero-Trust) و ایزوله شما مطابق با جدیدترین استانداردهای سال ۲۰۲۶ مستقر شده و آماده استفاده در دفتر مدیریت پروژه خواهد بود.
